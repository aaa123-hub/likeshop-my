# 后端与前端问题汇总

更新时间：2026-07-08

## 后端问题汇总

### 1. 小程序地理位置权限

- 微信小程序后台需要开通地理位置相关接口权限。
- 小程序隐私协议需要声明位置信息使用场景。
- `manifest/app.json` 的定位权限描述需要与微信后台配置保持一致。
- 需要真机验证 `wx.getLocation`、`wx.chooseLocation`，微信开发者工具显示暂无权限时不能作为最终判断。

### 2. 地图地址与订单关系

- 需要确认待付款/自提订单是否允许使用地图 POI 地址作为收货或自提地址。
- 如果订单必须绑定门店 ID，需要提供经纬度/关键词查询附近门店接口。
- 如果地图选点影响配送范围、运费或自提点合法性，需要提供重新校验或重新计价接口。
- 支付前是否需要保存地图选点信息，需要后端提供明确接口，或在支付创建接口接收对应字段。

### 3. 待付款优惠券

- 订单详情接口需要返回可用优惠券列表，例如 `usableCoupon`、`usable_coupon`、`availableCoupons`。
- 订单详情接口需要返回不可用优惠券及不可用原因，例如 `unusableCoupon`、`unavailableCoupons`、`tips`。
- 待付款订单更换优惠券后，需要重新计算金额的接口，或明确支付创建接口会按最新 `coupon_id/no_coupon` 重算。
- 支付创建接口需要确认接收字段：`coupon_id`、`couponIds`、`no_coupon`。
- 如果待付款订单已经锁价、不允许换券，需要后端返回明确业务错误，前端再按结果展示禁用或提示。

### 4. 支付与订单金额

- 支付创建接口返回金额必须作为最终支付金额。
- 优惠券、积分、运费、自提/配送方式变更后，后端需要保证金额计算口径一致。
- 支付结果页和订单详情页需要返回同一套优惠券抵扣、积分抵扣、实付金额字段，避免前端展示不一致。

### 5. 通用接口字段稳定性

- 商品详情字段需要稳定：商品图、SKU、规格、库存、价格、优惠券、评价、店铺信息。
- 订单字段需要稳定：订单状态、按钮权限、物流、自提、核销、退款、售后状态。
- 用户字段需要稳定：用户资料、手机号、优惠券列表、设置项。
- 图片上传需要返回公网可访问完整 URL，用于头像、售后凭证、评论图、资质图等场景。

## 前端问题汇总

### 1. 地图选点页面

- 地图选点目前只做前端缓存和页面回填，后续需要按后端接口保存到订单，或转成有效门店/配送地址。
- 需要补真机测试：定位拒绝、重新授权、地图选点、支付跳转、返回后缓存恢复。
- 微信开发者工具可能显示地理位置暂无权限，必须以后端/微信后台配置和真机验证为准。

### 2. 待付款优惠券

- 待付款页和确认订单页已修复“不使用优惠券”后再次选择可用券无法选中的问题。
- 待付款优惠券当前前端交互已修复，但最终金额是否变更仍依赖后端是否支持重新计价。
- 如果后端订单详情不返回优惠券列表，前端只能展示“没有可用的优惠券”。
- 如果后端支付接口忽略 `coupon_id/no_coupon`，前端选择不会影响最终支付金额。

### 4. 业务链路待验证

- 需要完整跑通交易链路：购物车、确认订单、创建订单、微信支付、支付结果、订单详情、售后申请。
- 需要完整跑通钱包和实名链路：余额、提现、流水、支付密码、KYC、商家资质。
- 营销类未闭环入口还需要根据后端状态继续隐藏、禁用或接入真实接口。

### 5. 工程与提交流程

- 当前工作区已有多处未提交改动，后续提交前需要按功能拆分检查，避免把无关改动混到同一次提交。
- 建议联调顺序：先定位权限和地图选点，再地址保存/门店映射，再待付款优惠券重算与支付创建，最后跑完整订单和售后链路。
